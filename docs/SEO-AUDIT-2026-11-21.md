# SEO audit — 2026-11-21

## Scope and method

Audited the repository and https://sopkit.space: all 493 sitemap URLs, 583 distinct internal link targets extracted from those pages, robots directives, HTTP status/redirects, canonical URLs, titles/descriptions, H1s, JSON-LD parsing, Open Graph metadata/images, registry integrity, content curation and blog length. Live findings describe the pre-change deployment; post-push verification is a separate step.

This is a technical and repository content audit, not a ranking, backlink or Search Console audit. No search analytics/property access was supplied. No ranking uplift or measured Core Web Vitals improvement is claimed. No experiments, analytics changes or new landing-page content were introduced.

## Findings and fixes

### Medium: 15 social metadata failures across 14 indexable pages

The original crawler passed because it did not validate social tags. A stricter crawl found:

- Inherited or incorrect `og:url`: `/editorial-policy/`, `/advertise/`, `/services/`, `/exam-image-tools/`, `/qr-tools/`, `/student-calculators/`, `/student-tools/`, `/business-tools/`, `/social-media-tools/`, `/converter-tools/`, `/finance-tools/`, `/ai-writing-tools/`.
- Missing `og:image`: `/editorial-policy/`, `/architecture-canvas/`, `/dev-speed/`.

These pages now use `constructPageMetadata`, producing page-specific social copy, normalized canonicals/OG URLs and the existing 1200×630 PNG image. The intent-page generator also now uses the shared helper instead of manually concatenating URLs, while preserving each route's indexing decision.

### Medium: the crawler could give a false clean result

`scripts/seo-audit-local.mjs` followed redirects, accepted slash/case-normalized canonicals, considered zero JSON-LD scripts valid, and did not check sitemap-page noindex directives or social metadata.

It now requires HTTP 200 without redirect following, exactly one canonical matching the sitemap URL, JSON-LD presence and parseability, indexable robots/googlebot metadata, matching OG URLs, OG titles/descriptions/images and Twitter cards. Attribute parsing accepts either ordering. Regression tests cover missing/invalid schema, noindex/none directives, duplicate/slashless canonicals and inherited/missing social metadata. `validate:page-metadata` also checks literal inputs to the shared helper so centralization does not remove length validation. New tests are included in `test:arch`.

### Medium, open: performance audit is simulated

`scripts/performance/lighthouse-all.ts` uses hardcoded, explicitly simulated values; `bun run perf:audit` exits successfully but does not run Lighthouse. Its scores must not be reported as measured performance or SEO results. Replace this with a real production Lighthouse/CrUX workflow in a separately scoped change. The managed local preview repeatedly invoked `next start` without a `.next` production build; the browser check could not render the app. Production builds are delegated to the existing GitHub Pages workflow, consistent with repository guidance against local production builds.

### Low, open: Cloudflare email protection link

The internal-link scan found one distinct HTTP 404: `https://sopkit.space/cdn-cgi/l/email-protection`, linked from `/privacy/`. No matching email-protection link exists in application source; this is consistent with edge email obfuscation. Inspect the actual contact interaction and Cloudflare email-protection configuration before changing it. Other 582 scanned link targets did not return HTTP errors; none of the 583 targets redirected.

### Content follow-up, not an automatic rewrite

All 49 blog articles meet the repository's 180-word floor, but 10 have fewer than 300 counted words. Passing a word-count floor is not evidence that an article satisfies search intent. Review these against actual queries and tool workflows, especially exam requirements, AI capability claims and broad SEO advice, before expanding, consolidating or noindexing. The uniqueness audit reproduced the same 113 curated IDs; only its generation timestamp changed and that noise was reverted. Existing thin/duplicated-prose gates were preserved.

## Passing baseline checks

- 493 sitemap URLs: HTTP 200, unique titles/descriptions, one self-referential canonical, no detected robots/googlebot/header noindex conflict, one H1, sufficient total HTML text by the existing crawler's heuristic and parseable JSON-LD.
- Social image URLs discovered in the initial live scan returned image content successfully.
- HTTP and www variants redirect to the HTTPS apex; slashless tool URLs redirect to trailing-slash routes. A deliberately nonexistent route returns 404.
- Registry: 464 tools across 20 categories, no duplicate IDs/routes.
- Sitemap policy: 493 listed URLs checked against 38 excluded/non-indexable/redirect routes, no violations.
- Last-modified data: coverage for all 464 tools and 16 distinct dates.
- 206 blog-tool references across 49 articles resolve; 18 SEO opportunities pass related-tool/category validation.
- `bun run typecheck`, `bun run test:arch`, `bun test tests/seo/`, all targeted SEO validators, `bun run audit:blog`, `bun run audit:content`, and LLM index generation passed before push. The SEO directory run passed 129 tests, including 21 new regression cases.
- The strengthened pre-deployment `bun run seo:audit --all` correctly exits nonzero for the 15 live metadata failures above. It must be rerun after deployment before declaring the live fixes verified.
